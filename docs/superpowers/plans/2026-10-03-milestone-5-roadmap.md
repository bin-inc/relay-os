# Milestone 5 Roadmap

**Spec:** `docs/superpowers/specs/2026-10-02-programmable-shell-gate-design.md` (the programmable shell gate; milestone 5 is its second half, "Redirection and environment", version 0.6.0)

**Status:** Done. All four plans were executed; milestone 5, and with it the programmable shell gate, ended at version 0.6.0 (tag `v0.6.0`).

Milestone 5 finishes the programmable shell: every standard stream can be redirected, compound commands included (`<`, `2>`, `2>>`, `2>&1`, `1>&2`), programs get an environment (ABI 4), `/dev/null` exists, the shell exports variables and runs `A=1 cmd`, `/bin/env` lists and changes an environment, `cd` follows `HOME`, `PWD` and `OLDPWD` (`cd -`), and the check scripts pass from any directory (spec §7–§9). It is split into the four plans of spec §12, named `m5-plan-1` to `m5-plan-4` (their files `docs/superpowers/plans/<date>-m5-plan-<n>-<name>.md`, their branches `m5p<n>/…`). Each one ends with software that can be tested by itself. Each plan is written just before it is executed, so it builds on the code that actually exists and on what the previous plan's checks showed.

## Notes carried forward

- **CI and pull requests (all plans).** As in milestone 4: every pull request to `main` must pass `lint`, `unit` and `e2e`; every plan is split into PRs that are each green on their own, one branch and worktree per PR; new crates, user packages and scenarios are picked up by `cargo xtask ci`. Commits and PR titles follow `CONTRIBUTING.md`.
- **How plans are made (all plans).** As in `AGENTS.md`: every task prototyped in a clone under `tmp/m5p<n>/proto`, one commit per task, tagged `t1..tN` on a tag `p0` (`origin/main` plus the plan's first PR's docs); the plan generated and replayed from it by `tmp/m5p<n>/gen` (a copy of milestone 4's, `tmp/m4p4/gen`); an independent review of the prototype whose real findings become tasks of their own, each with a test that fails first; a spike first when the risk is "does everything still pass".
- **bash is the reference, in a pty for the prompt.** `tmp/m4p2/pty_bash.py` runs an interactive bash 5.2.21; the bash corpus runs host bash on every `cargo xtask unit`, and CI's ubuntu-24.04 has bash 5.2.21.
- **No cut line** (spec §1.2): milestone 4 took a few days of the gate's one to two months, and redirection of compound commands (§7.4), the first item to cut, is the same fd context that several redirections on one command need.
- **Plan 1 changes no ABI** (spec §15 item 5): `spawn` already maps any fd of the caller to each of the child's, and hands the child the caller's open file, whose offset they share; `/bin/sh` maps all three of a command's fds.
- **ABI 4 is plan 2's, in one bump:** `SpawnArgs` gains `env` and `env_len`, and `StatFs` a flag that says a filesystem is read-only (its layout changes too, so both are one `VERSION` 4, one `!` commit with a `BREAKING CHANGE:` footer). It ripples into `t-abi` (built for ABI 3, `STALE_ABI`), the startup line `ABI 4`, check 3's `dmesg` expectations and transcripts (the NUC's by hand until plan 4), `docs/hardware-test.md` and the `system` scenarios.
- **For plan 2 (`statfs`):** `test -w` answers false on every read-only filesystem with the flag, as GNU does, ending §10's difference (spec §15 item 3; milestone 4's plan 3 found the root mounted read-only after an `EIO`).
- **For plan 2 (`/dev/null`):** `relay_rt::sysio::is_console` takes a character device on filesystem 0 to be the console, so `/dev/null` must not report filesystem 0 with that kind, or `test -t` and the shell would take it for the console. QEMU's root disk has a `/dev` directory already (plan 1's spike made a file in it with `> /dev/x`): the mount stands over it, and nothing should depend on what lies under it.
- **No NUC check before plan 4.** Plans 1–3 change the shell, the ABI and the check scripts' first line; the stick keeps 0.5.0 until plan 4's `flash --full`, and plan 4's `check7.sh` runs redirection and the environment there. Plan 2's `ABI 4` and plan 3's `+ cd /root` lines reach the NUC transcripts by hand until then, as milestone 3's plan 1 did for `ABI 3`.
- **Milestone 4's plan 4's deferred minors** (`tmp/m4p4/plan-ledger-final.md`): M-2 (`((a); b)`, two subshells to bash with no here-document, drops the rest of a dropped script silently) goes to plan 1 with the drop scan's two older gaps (quotes inside `$(…)` inside double quotes end the scan's quote early; `time -p {` and `coproc {` are command positions the scan does not know), as plan 1 changes the parser's redirections and checks the scan against them; M-3 (an mcopy failure with an empty standard error leaves `verify-usb`'s `…on the ESP: ` empty) goes to plan 4.
- **For plan 4 (`X | sh > f`):** a shell whose own fd 1 is a file (`X | sh > log`) writes a built-in's standard output, and its own messages and a built-in's after `2>&1` or `1>&2`, to the screen, since relay-rt's console writes fd 2 (milestone 3's built-ins already did; plan 1's review, M-3, the maintainer's choice to settle it in plan 4). Programs are not affected.
- **Rulings of milestone 4 that still hold:** `host-shell` cannot end a loop at Ctrl-C and its `test -t` is always false (a developer's tool); `X | sh` keeps `\r`, as since milestone 1; a script's unterminated quote drops the lines up to the one that closes it; `key-ahead {ctrl-c}x` (keys after a Ctrl-C mid-text) is allowed.
- **Plan 1's deferred minors** (`tmp/m5p1/plan-ledger-final.md`): the sentence of spec §15 item 5 on `grep`'s input that is the output is corrected in §15 item 6; a failed redirection after `2>&1` on a pipeline's earlier stage tells its message on the screen, not into the pipe (`cat 2>&1 < /nope | wc -l`: bash prints `1`), and a refusal drops an explicit default fd (`1> f | cat` → `> before |`, `0< f | cat` → `< before |`): both go to plan 4.
- **Plan 1's rulings that still hold:** `a > /nodir/x &` starts no job, status 1, where bash starts it; `grep -q` leaves its input after its 4 KiB read, where GNU reads 96 KiB.
- **Plan 2 changes the ABI and adds `/dev`** (spec §15 item 6): `VERSION` 4 for `SpawnArgs::env` and `StatFs::flags` in one `!` commit; the kernel mounts `/dev` before `/bin`, so `/bin` becomes filesystem 3; `df` still lists only `/` (the maintainer). It has no NUC check: check 3's `ABI 4` and `[ ok ] dev: /dev/null` lines reach `check3-a.nuc.log` by hand until plan 4.
- **For plan 3 (the environment):** until `export`, `/bin/sh` hands its whole environment to every command (`SysPrograms` passes the program's own block); plan 3 passes the exported variables instead, and gives relay-rt's test double its environment (§8.3).
- **The user stack stays 255 pages** (spec §13, §15 item 6): plan 2's spike measured `/bin/sh` at 40 KiB at the nesting bound, the deepest of any program, against 892 KiB left when both 64 KiB blocks are full.
- **Plan 2's deferred minors** (`tmp/m5p2/plan-ledger-final.md`): plan 3 settles m-7 (README's crate table) and m-8 (`t-env raw`'s `1 entries`, and relay-rt's environment tests sharing one static); m-2 (`kernel/src/file.rs`'s module comment on a device's `seek`), m-3 (the `FileSystem` contract's sentences that `DevFs` does not keep), m-4 (`xtask/src/userland.rs`'s `3 -> 2`) and m-5 (`check3-b.nuc.log` without the `dev` line, `check3-a.nuc.log`'s `44 programs`) go to plan 4.
- **Plan 3 changes no ABI** (spec §15 item 7): `spawn` already takes an environment; `Programs::spawn` in the shell gains the block, and `/bin/sh` builds it from its exported variables.
- **For plan 4 (the NUC transcripts):** plan 3's `+ cd /root` lines reach every `*.nuc.log` by hand, beside plan 2's `ABI 4` and `dev` lines; plan 4's NUC run records them all again.
- **Plan 3's deferred minors** (`tmp/m5p3/plan-ledger-final.md`): m-1 (a held assignment past `VARS_MAX`), m-2 (`export A+=b`'s message), m-3 (`parser.rs`'s module comment on `~` and `A=1 cmd`), m-4 (§15 item 7's `OLDPWD` sentence, corrected in item 8) and m-5 (`/bin/env` with Ctrl-C and a killed command on target) go to plan 4 (spec §15 item 8).
- **Plan 4 changes no ABI** (spec §15 item 8): its fixes are in the shell, xtask and the scenarios; `check7.sh` and version 0.6.0 change the check scripts' transcripts, which the NUC run records again.
- **Still out of the gate** (spec §14): command substitution, arithmetic, globbing, word splitting, functions, `case`, `break`, `continue`, `read`, here-documents, subshells; `PATH`, `CDPATH`; users, an editor, interrupts, floating point, networking, other architectures.
